# Async response correlation extension

## Intent and preserved scope
User asked to continue as far as possible. Add request-correlated handling of out-of-order refresh completions while retaining the synchronous library behavior and all original native/contract/formal/mutation gates. No OS threads, network, crypto, real credential objects or package distribution. Events remain serialized and atomic; asynchronously arriving responses are represented as tagged input events. This is response-correlation state management, not a thread-safe network client.

The optional user question about Refreshing×Logout is unanswered. The binding existing specification says ignore it. Preserve that explicitly existing policy until the user steers it; do not silently infer approval of cancellation. The new async profile lives inside the sole authority contract/specification.json v3. Flat core table remains behavior-identical to v2. Each new typed adapter may reuse its own language's native reducer, never the other language's code or a specification interpreter.

## Complete async contract
`async.transitions` enumerates the same full state×event domain. A response row's `activeResponse` guard is true only in Refreshing with a non-null pending ID equal to the response ID. Guard failure preserves state, pending ID and next-ID availability, produces no effects and no rejection. An `always` guard applies the row normally.

Initial default: Unauthenticated, pending ID null, next ID 1. Request IDs are positive signed 64-bit integers through 9223372036854775807, scoped to one logical session object. Allocation happens only for Authenticated×TokenExpired. It yields RequestTokenRefresh carrying the allocated ID, enters Refreshing and stores that pending ID. Advance next ID without wrapping/reusing; after the maximum is allocated next availability is null. If allocation is unavailable, return RequestIdExhausted with unchanged state/pending/counter and no effects. This is a domain rejection, not malformed input.

Matching RefreshSucceeded/Failed clears pending ID and uses declared state/effects. Authenticated Logout clears pending (already null); other rows preserve pending unless declared otherwise. ClearCredentials has no request ID; RequestTokenRefresh has its allocated ID. ID counter is never reset on logout/login/refresh completion. Current policy: Refreshing Logout is ignored and does not cancel its request. Stale, duplicate, unissued-ID and responses after session changes are ignored unless exactly matching the current pending ID. Responses must be routed to the same logical session instance: IDs alone do not distinguish foreign instances or provide security authenticity.

Public async construction defaults to next ID1. An optional valid starting next ID supports boundary testing; state remains initial and pending null. Existing core constructor/API/runner stay unchanged. New synchronous handle API uses typed events/results, exposes state/pending ID, and returns a typed rejection or result. Library calls require caller serialization; no Sendable/thread-safety claim for shared mutable adapters.

## Wire interface
Separate AsyncTraceRunner, preserving old TraceRunner. Input:
`{"scenarios":[{"scenario":"id","events":[{"event":"LoginSucceeded"},{"event":"TokenExpired"},{"event":"RefreshSucceeded","requestId":1}]}]}`.
A scenario optionally has `nextRequestId` (valid signed64 positive seed); otherwise1. Only responses require requestId; other event objects contain exactly event. IDs are JSON integer tokens in the positive signed64 range, not bool/string/fraction/exponent. Unknown/malformed input, duplicates or extra keys reject the entire document with stderr, nonzero exit and no partial stdout.

Output `{ "traces":[{"scenario":"id","steps":[{"event":<input event object>,"state":"Refreshing","pendingRequestId":1,"effects":[{"effect":"RequestTokenRefresh","requestId":1}],"rejection":null}]}] }`. Every step has exactly event/state/pendingRequestId/effects/rejection. Clear effect object contains only effect. Rejection is null or RequestIdExhausted; a valid exhausted event still yields a step, with no effects or mutation. Compare all meaningful ID payloads and ordered effects, not runtime metadata. Kotlin installed async runner path android/async-library/build/install/async-library/bin/async-library; Swift ios/.build/debug/AsyncTraceRunner.
