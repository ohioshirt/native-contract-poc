# Reproducible contract evolution design

Date: 2026-10-12. Baseline: 8458f66. Status: APPROVED after independent review R1–R5 on 2026-10-12.

## Intent and authorization
The user requested decomposition into work lower models can execute, subagent review, then actual lower-model execution. This authorizes the sequence without repeated human design/plan approval. Parent owns requirements and coordination; Sol reviews and implements verification/integration, Luna implements bounded native changes. No publishing or main-branch merge is included. Evidence must contain real commands and raw tails; unavailable metrics are null, never guessed.

## Scope and alternatives
Deliver the four requested improvements: reproducible change protocol, async Logout invalidation, checkable session/ID ownership, and concurrent history checking. Preserve synchronous behavior and existing low-level APIs. Add a managed facade rather than break or silently reinterpret Swift value semantics. A documentation-only assumption ledger is insufficient; replacing all low-level APIs is unnecessary. The facade gives one authoritative mutable session, unforgeable in-process request ownership, and serialized transitions. No real network, credential persistence, transport cancellation, restart recovery, or liveness guarantee.

## A. Logout contract v4
The unique behavior authority remains contract/specification.json. Keep core table byte-for-byte semantically unchanged. Set async.logoutWhileRefreshing to invalidate and change only async (Refreshing, Logout): nextState=Unauthenticated, effects=[ClearCredentials], guard=always, pendingAction=clear. nextRequestId is preserved including null exhaustion. Repeated Logout in Unauthenticated emits nothing. Both stale success and failure emit no effects and no rejection, preserving the entire state, pending and allocator after Logout, subsequent LoginSucceeded and a new TokenExpired. Fresh response still works. Preserve the ignore profile as a valid historical mode if its row exactly matches old behavior; other core/async differences remain invalid.

Schema and semantic validator must support the explicit mode and enforce exactly its permitted difference, totality, closed domains, effect bounds and pending iff Refreshing. Add policy properties independent of generated row expectations, and mutations for ignored Logout, missing ClearCredentials, uncleared pending and counter reset. Native workers cannot modify the fixed spec, oracle, formal model or evaluator. Build failure is infrastructure failure, not successful mutation detection. Old native implementation must fail the NEW behavioral oracle with valid new schema before workers start.

## B. Reproducible change protocol
Add a Python stdlib CLI that freezes a manifest of baseline commit, change ID, file SHA-256 values (contract/schema/verifier/formal/scripts), allowed native paths and experiment metadata; checks immutable inputs before/after evaluation; captures argv, cwd, UTC start/end, monotonic duration, exit status, stdout/stderr and verdict in isolated per-attempt directories. Never delete unowned outputs. Detect changed protected inputs and out-of-scope source edits. Distinguish PASS / SEMANTIC_FAIL / INFRA_FAILURE / NOT_RUN. Capture subprocess timeout as infrastructure failure; exit 1 alone is not universally semantic failure (only a specified comparator protocol). No provider API or invented cost fields. Report timeout/repair budget exhaustion as stopped, never passed. Use one frozen evaluator across attempts; evaluator fixes require a new manifest and invalidation/re-evaluation of affected attempts.

Protocol stages: baseline evidence -> reviewed change/spec/verifier -> freeze -> old implementation semantic RED -> candidate -> fixed evaluation -> bounded repair -> repeat -> final evidence. Record explicit model IDs, reasoning effort, arm, seed, caches, limits, interventions and all attempts. For future Sol+Luna vs Luna comparison, distinguish workflow comparison from model-only comparison, balance order, use identical task inputs/baseline/evaluator and per-arm clean writable trees; document build and provider caches separately. No general superiority claim from a pilot. This run uses parent coordination, actual lower-model workers and independent Sol reviews; do not relabel parent as Sol.

## C. Managed session ownership and serialized API
Add ManagedAsyncSession per platform. Swift actor; Kotlin private lock with synchronized critical section (existing JVM target needs no coroutine dependency). Existing AsyncSession stays low-level caller-serialized. Managed session owns exactly one low-level session and exposes handle and snapshot only; no restore/copy/seed mutation API. Snapshot is immutable and contains state/pendingRequestId/nextRequestId. Swift actor references alias the same history. Kotlin object references likewise. Initial constructor may accept positive nextRequestId for boundary testing, but creates a distinct owner each time.

ManagedEvent: LoginSucceeded, Logout, TokenExpired, RefreshSucceeded(RefreshRequest), RefreshFailed(RefreshRequest). RefreshRequest is an opaque immutable object with public requestId, internal owner identity, and no public initializer/copy/deserializer. It is emitted only by ManagedEffect.RequestTokenRefresh(request). Identity is a retained reference object, NOT UUID probability or a caller-supplied string. ManagedEffect.ClearCredentials has no token. Response from another owner returns unchanged snapshot, no effects, rejection ForeignRequest. Matching-owner responses delegate to numeric correlation; stale/duplicate responses remain no-ops. Managed rejection also includes RequestIdExhausted. A caller can reuse a legitimate token; it cannot forge one for another owner through the public API.

ManagedResult contains coherent snapshot, ordered effects and optional rejection. The complete validation/reduction/token-creation/snapshot operation is atomic: Swift actor handle has no internal await, Kotlin whole operation holds one private monitor. snapshot uses the same actor/monitor. Effects are descriptions returned to callers; their real execution order is outside the guarantee. No callback or I/O while locked. Swift immutable event/result/state types must be Sendable. Core AuthState is already Sendable; no core source changes are permitted.

## D. Formal correspondence and concurrency evidence
Document abstraction alpha(native)=(state,pending,next,owner); distinguish enforced ownership at managed facade from assumptions retained at low-level API. Add an explicit finite numeric Python model explorer using two owners, IDs 1..3, exhausted sentinel and issued-ID history, derived transitions from the v4 profile. Explore reachable product states with exhaustive successor generation; check pending iff Refreshing, no ID reuse, atomic exhaustion, owner isolation and post-Logout stale safety. Show named negative controls (allocator reset and owner check removed) produce concrete counterexamples. Bound is explicit; this is no native refinement proof or proof for all signed64 values. Existing TLA+ remains and gains Logout policy invariant/negative control if necessary; native boundary tests cover Int64/Long maximum.

Add a common Python linearizability checker against the JSON oracle for COMPLETED managed handle histories. Each history includes initial next ID per owner and each operation's unique ID, owner, input event/token owner+ID, invocation and return logical timestamps, coherent result snapshot/effects/rejection. A history satisfies iff there exists a sequential permutation preserving return(A)<invoke(B), session ownership semantics and observed output at every step. Snapshot operations are required in both the frozen workload and observed histories. Reject malformed/duplicate/missing operations; bound search size and report budget exceeded as INCONCLUSIVE, never PASS. Never compare Swift and Kotlin's arbitrary scheduling orders for equality.

Native harnesses use actual concurrent callers (Swift TaskGroup, Kotlin threads/executor) with a shared synchronized timestamp recorder around calls. Produce small bounded histories in JSON, include non-overlap phases and overlap phases, stale and foreign tokens, Logout versus completion, simultaneous TokenExpired, and concurrent snapshots. A sequential projection is accepted only by external checker, not implementation-written expected outcomes. Unit test checker with impossible return values, illegal real-time reorder, missing operations, foreign-owner acceptance, and a legal overlapping reorder. Native seed controls reproducible scenarios, not OS scheduling; record observed history as replay artifact. Invalid-history and known mutant controls must be rejected. Integrate all new gates with scripts/verify.sh and CI via existing entry point.

## Acceptance and limits
Run baseline and final existing full gates, new protocol/checker/model tests, native managed tests and actual histories, all mutation controls, then independent review. Retain logs under reports/evolution and summarize committed evidence under docs/experiments with actual command and tails. Sync contract unchanged; async behavior intentionally changes, documented as v4 behavior change. No source-to-source independence claim stronger than isolated contexts and explicit read restrictions. No whole-program equivalence, unbounded concurrency, transport safety or measured model ranking claim.

## Review resolutions: normative execution detail

R1: The manifest freezes named stages: exact argv templates with only candidate/output path substitutions, cwd, timeout, artifact validation and verdict protocol. run selects a stage; arbitrary argv/protocol changes are refused. Each record binds manifest SHA-256, candidate source digest, stage ID, attempt ID, fresh uniquely owned output and raw logs. Required artifact freshness/shape/verdict are checked before PASS. Async comparison exit1 is SEMANTIC_FAIL only when the actual async-report.json proves semantic native mismatches; INFRA_FAILURE/NOT_RUN outrank semantic results. Aggregate full-gate exit1 is infrastructure/aggregate failure, never automatically semantic. Full-gate exit0 plus report.md Overall: INCOMPLETE cannot PASS. Include protocol code and scripts in protected membership. Track all source membership against frozen reviewed inputs, not merely baseline HEAD; explicit generated-output and evidence exclusions are recorded. The authoritative manifest digest lives in controller evidence. This detects accidental/unauthorized edits by cooperative workers, not a malicious actor rewriting both controller and manifest.

R2: Complete/review protocol, v4 verifier, history checker/model, mutation drivers and normal gate wiring BEFORE freeze. Native mutation exact snippets are frozen in a separate native-anchors.md brief; sources later implement them. Validate matrix patches against these fixture snippets before source exists. Task 5A creates evaluator, Task 6A integrates evaluator and documentation; 5B/6B only run and record evidence. Missing future runners are NOT_RUN/non-PASS. Preserve/hash old native binaries and distribution, run behavioral RED using those artifacts. Any later evaluator fix requires a new manifest revision, new reviewed digest, rerun of old-native RED and candidate stages; retain superseded records marked invalidated.

R3: A verifier-owned frozen scenario workload independently enumerates owner declarations, all operation IDs including setup/snapshot calls, kind/event templates and phase/dependency edges. Runners consume it; checker compares exact operation membership/input metadata with it. Responses reference a prior producing operation effect via tokenRef={operationId,effectIndex}; renderer also records owner/ID. Producer must have emitted that actual token and recorded return before response invocation; token owner/number must agree. Do not accept forged/future tokens or unrecorded initial fixtures. Tokens become available to later phases only after producer return. Shared strictly increasing logical timestamps are recorded immediately before and after each API call/await through one short serialized recorder; recorder lock is never held over API execution. All timestamps unique; invoke<return; phase/dependency edges validated. snapshot has no event/effects/rejection, observes the full triple and leaves it unchanged. Join every task/future; missing/failed calls are non-PASS. Operation and search bounds must be explicit in frozen guide. Concurrent workload phases need multiple live callers; scheduling need not actually overlap every invocation interval, and a lack of observed overlap is reported as insufficient concurrency coverage rather than a proof of safety. Deterministic scheduler seeds are not claimed. Separate small histories keep checking tractable.

R4: RefreshRequest is final and immutable, with no public constructor/copy/serialization or owner/low-level-session access. Claim applies to ordinary external source API clients, excluding reflection/unsafe/runtime attacks and privileged test access. Effects are detached immutable collections; Kotlin mutable-list casts cannot mutate retained results. External compile probes (without Swift @testable or Kotlin friend paths) demonstrate emitted token reuse allowed and constructor/owner/session access refused. Add one stable owner-guard native mutation per language; real deterministic same-number foreign-token workload must semantically reject each mutated facade after successful build. Neither numeric-model mutation nor synthetic checker mutation substitutes for this native control.

R5: Task 2 publishes verification.async_contract.step(spec, state, pending, next_id, event, *, request_id_max=None) -> dict with state,pendingRequestId,nextRequestId,effects,rejection. event is normalized event object. Production bound defaults to signed64 from spec; only finite explorer/tests pass max=3. Normal schema remains signed64, so finite instantiation is not presented as a valid production contract. Existing low-level oracle trace wire omits nextRequestId as before and delegates transitions to step. Numeric explorer independently implements finite transition rules derived from rows and checks each full triple/effect/rejection step against this oracle with test bound. Two fixed owner identities each start (Unauthenticated,None,1), with ghost issued-ID sets. Generate all simple events and both responses using every actually issued token, addressed to each owner, plus snapshots. Same numeric ID across owners is allowed; reuse within one owner is forbidden. Ghost history belongs to proof instrumentation, not native snapshots. Check no-reuse/monotonic allocator, exact exhaustion, foreign-owner unchanged triple, pending iff Refreshing, canceled/stale no-op. Reset and owner-check-removed model mutants must produce concrete intended-invariant counterexamples. Native MAX boundary tests remain required; finite correspondence is not unbounded native refinement.
