# Managed workload and completed history format, version 1

`verification/managed-workload.json` is the evaluator-owned operation inventory. Runner stdin is that entire document; runner stdout is JSON only. JSON integers are exact signed64 values, never floating-point conversions. Seeds select workload inputs, not OS scheduling. The current frozen scenario seed is 0. One scenario creates new independent owners, each initially `(Unauthenticated,null,nextRequestId)`. No initial tokens exist.

Workload shape (all keys are mandatory and no extra keys are allowed):

```json
{"version":1,"scenarios":[{"id":"example","seed":0,"owners":[{"id":"A","nextRequestId":1}],"concurrentPhases":[],"operations":[{"id":"login","owner":"A","kind":"handle","phase":0,"after":[],"event":{"event":"LoginSucceeded"}},{"id":"issue","owner":"A","kind":"handle","phase":1,"after":[],"event":{"event":"TokenExpired"}},{"id":"reply","owner":"A","kind":"handle","phase":2,"after":[],"event":{"event":"RefreshSucceeded","tokenRef":{"operationId":"issue","effectIndex":0}}},{"id":"view","owner":"A","kind":"snapshot","phase":3,"after":[]}]}]}
```

`phase` is a nonnegative integer. Every operation in an earlier phase must return before any later phase invocation. `after` contains additional predecessor operation IDs, with predecessor return before invocation. A response's `tokenRef` must name an earlier producing call and effect index; it creates an additional producer-return-before-response-invoke edge. Runner stores emitted actual request objects, keyed by producer ID/effect index, only after recording the producer's return. Do not manufacture tokens from rendered numbers. `snapshot` has no event. Simple events are LoginSucceeded/Logout/TokenExpired; response kinds are RefreshSucceeded/RefreshFailed.

History shape:

```json
{"version":1,"histories":[{"scenario":"example","seed":0,"trial":0,"owners":[{"id":"A","nextRequestId":1}],"operations":[{"id":"login","owner":"A","kind":"handle","phase":0,"after":[],"event":{"event":"LoginSucceeded"},"invoke":1,"return":2,"result":{"snapshot":{"state":"Authenticated","pendingRequestId":null,"nextRequestId":1},"effects":[],"rejection":null}},{"id":"issue","owner":"A","kind":"handle","phase":1,"after":[],"event":{"event":"TokenExpired"},"invoke":3,"return":4,"result":{"snapshot":{"state":"Refreshing","pendingRequestId":1,"nextRequestId":2},"effects":[{"effect":"RequestTokenRefresh","token":{"owner":"A","requestId":1}}],"rejection":null}},{"id":"reply","owner":"A","kind":"handle","phase":2,"after":[],"event":{"event":"RefreshSucceeded","tokenRef":{"operationId":"issue","effectIndex":0},"token":{"owner":"A","requestId":1}},"invoke":5,"return":6,"result":{"snapshot":{"state":"Authenticated","pendingRequestId":null,"nextRequestId":2},"effects":[],"rejection":null}},{"id":"view","owner":"A","kind":"snapshot","phase":3,"after":[],"invoke":7,"return":8,"result":{"snapshot":{"state":"Authenticated","pendingRequestId":null,"nextRequestId":2},"effects":[],"rejection":null}}]}]}
```

Each history must contain exactly the declared operations once, with exact input/phase/dependency metadata; array row order is irrelevant. History scenario membership is exact too. Owners must equal the declarations. A rendered response adds `token:{owner,requestId}` to its workload event; tokenRef remains present. Request effects have exactly `effect,token`; ClearCredentials effects have exactly `effect`. Rejection is null, ForeignRequest, or RequestIdExhausted. Every result observes the complete triple and ordered effects. Snapshot results have empty effects and null rejection and do not transition.

A single short serialized recorder per history produces globally unique positive integer invocation and return stamps across all owners. Record invocation immediately before the API call/await and return immediately after it; invoke < return. Recorder lock is never held over the managed call. All real-time constraints `return(A)<invoke(B)` are enforced, including same-phase calls. Producer return is strictly before consuming invocation and rendered token equals the actual observed producing effect. Native exceptions/cancellation/missing calls must return nonzero; completed subsets cannot pass.

Native phases launch actual TaskGroup callers / threads behind one common start barrier before invocation recording. Join every caller before the next phase. `concurrentPhases` require at least one pair of overlapping invocation intervals in each named phase (a snapshot may be one of the pair). No overlap is insufficient coverage, reported INCONCLUSIVE even if a sequential witness exists. Up to 20 whole-scenario trials (trial 0..19) are permitted; return one complete observed trial, not a mixture. The schedule itself is not deterministic and Swift/Kotlin histories are checked separately, without comparing schedule order.

Default checker bounds: at most 16 operations per history, 1,000,000 search nodes, 10 monotonic seconds per history. A bound reached is INCONCLUSIVE and never PASS. A witness must satisfy every observation and real-time edge; exact result equality includes allocator, pending ID, effect order, token owner/number and rejection. INVALID_HISTORY diagnoses malformed/incomplete/provenance-invalid records; FAIL means well-formed observations admit no sequential witness; INCONCLUSIVE means search or concurrency coverage is insufficient. CLI emits a JSON report and exits 0 only for PASS, 1 for FAIL/INVALID_HISTORY, 2 for infrastructure, and 3 for INCONCLUSIVE. Normal gate retains these distinctions.
